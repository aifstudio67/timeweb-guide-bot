# Бот для выдачи гайда Timeweb Cloud

Бот проверяет подписку на Telegram-канал и только затем отправляет PDF. После выдачи он сохраняет источник, факт получения, интерес к типу проекта и запрос на помощь в PostgreSQL.

## Что умеет

- `/start` показывает кнопку подписки и кнопку проверки;
- проверяет пользователя через Telegram `getChatMember`;
- отправляет `assets/timeweb-cloud-app-deploy-guide.pdf` только подписчику;
- сохраняет лиды и события в PostgreSQL;
- принимает deep-link источники, например `?start=ig_reel_01` и `?start=youtube_short_01`;
- предоставляет `/health` для проверки состояния в Timeweb Cloud.

## Перед запуском

1. Создайте бота у [@BotFather](https://t.me/BotFather). Токен не отправляйте в чат и не коммитьте в GitHub.
2. Создайте канал или используйте существующий. Добавьте бота в администраторы канала. Право на публикацию ему не требуется, но статус администратора нужен, чтобы надёжно проверять подписку.
3. Подготовьте адрес канала:
   - публичный: `CHANNEL_ID=@my_channel`, `CHANNEL_URL=https://t.me/my_channel`;
   - приватный: `CHANNEL_ID=-100...`, `CHANNEL_URL=<пригласительная ссылка>`.
4. Создайте PostgreSQL в Timeweb Cloud и получите строку подключения. Без базы бот сможет технически отвечать, но не будет выполнять свою задачу по накоплению лидов, поэтому `DATABASE_URL` обязателен.

## Локальный запуск

```powershell
Copy-Item .env.example .env
npm install
npm test
npm run dev
```

Заполните `.env` только на своём компьютере. Этот файл исключён из Git.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather; хранится только в секретах Timeweb |
| `CHANNEL_ID` | `@username` публичного канала или числовой ID приватного |
| `CHANNEL_URL` | ссылка на канал или инвайт-ссылка |
| `DATABASE_URL` | строка подключения PostgreSQL |
| `DATABASE_SSL` | `true`, только если это требует инструкция к базе |
| `PORT` | порт HTTP-сервера, по умолчанию 3000 |
| `GUIDE_FILE_PATH` | путь к PDF, по умолчанию уже настроен |

## Деплой в Timeweb Cloud App Platform

1. Запушьте эту папку в отдельный GitHub-репозиторий. PDF из `assets/` должен попасть в репозиторий.
2. В Timeweb Cloud откройте **App Platform** → **Добавить** → подключите GitHub-репозиторий.
3. Выберите backend-приложение Node.js и Node.js 22. Укажите одну реплику: long polling не должен запускаться одновременно в нескольких экземплярах.
4. Укажите команды:
   - сборка: `npm ci`;
   - запуск: `npm start`.
5. В расширенных настройках установите путь проверки состояния `/health`.
6. Добавьте все переменные из `.env.example` в разделе «Переменные». Реальный токен добавляйте только здесь.
7. Запустите деплой. При ошибке сначала посмотрите вкладку «Деплой» в панели Timeweb.

Приложение слушает `0.0.0.0` и использует `PORT`, поэтому подходит для App Platform. Бот работает через long polling: отдельный домен и webhook не нужны.

## Ссылки для видео

После того как @BotFather выдаст username бота, используйте ссылки:

```text
https://t.me/<bot_username>?start=ig_reel_01
https://t.me/<bot_username>?start=telegram_story_01
https://t.me/<bot_username>?start=youtube_short_01
```

Источник попадёт в базу. Не меняйте формат параметра: Telegram допускает в нём только латинские буквы, цифры, `_` и `-`.

## Перед публикацией

- Проверьте выдачу с другого Telegram-аккаунта.
- Нажмите «Проверить и получить гайд» до и после подписки.
- Убедитесь, что бот назначен администратором именно нужного канала.
- Добавьте ссылку на политику обработки персональных данных до запуска рекламы или массовых рассылок.
